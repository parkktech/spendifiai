<objective>
Prove and harden the prompt-injection defense across every content path and the SSN-masking chain (SAFE-02, SAFE-04, SAFE-07).

Purpose: Binary document/image content is not text-injectable, but the STRUCTURED-JSON-SCHEMA output validation is the actual guard — and today TaxDocumentExtractorService::sanitizeExtraction() does NOT drop fields outside the category schema, so an injected instruction that makes Claude emit an assertive field would survive. Two v1.0 paths (email parser, statement text fallback) interpolate raw content with no delimiters. SAFE-04 has code but no end-to-end masking audit.

Output: Additive output-validation (schema whitelist) on extraction, additive <document_content> delimiter wrapping on the two text paths, and two pen-test/audit suites that fail if any defense regresses. Additive only — no existing field, response shape, or model relationship changes.
</objective>
