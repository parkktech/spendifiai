**CLOSED: Bank sync marks the optimization report stale (RPT-02 complete)**

**Previously:** Bank sync (SyncBankTransactions / PlaidController::sync()) did not dispatch BuildIncomeOptimizationProfile, so the staleness chain was incomplete.

**Fix:** Commit 5ef798a added line 60 to `SyncBankTransactions::handle()`:
```php
BuildIncomeOptimizationProfile::dispatch($user->id, now()->year);
```

This dispatch is placed after every successful Plaid sync (added / modified / removed), ensuring BuildIncomeOptimizationProfile fires OptimizationProfileBuilt, which the already-wired listeners `MarkOptimizationReportStale` and `DispatchReportGeneration` handle.

**Verification:** New test case in `ReportStalenessTest.php` (lines 239–267) asserts the dispatch and passes:
```php
test('bank sync dispatches BuildIncomeOptimizationProfile to trigger the staleness chain (RPT-02)', function () {
    Queue::fake();
    ['user' => $user, 'connection' => $connection] = createUserWithBank();
    $taxYear = now()->year;
    OptimizationReport::create([...]);
    $plaid = Mockery::mock(PlaidService::class);
    $plaid->shouldReceive('syncTransactions')->once()->andReturn(['added' => 3, 'modified' => 1, 'removed' => 0]);
    app()->instance(PlaidService::class, $plaid);
    $job = new SyncBankTransactions($connection);
    $job->handle($plaid);
    Queue::assertPushed(BuildIncomeOptimizationProfile::class, function ($queued) use ($user, $taxYear) {
        return $queued->userId === $user->id && $queued->taxYear === $taxYear;
    });
});
```
