<decisions>
## Implementation Decisions (LOCKED unless marked default-ruling)

### D1 — Report architecture (RPT-01/02)
`OptimizationReportGeneratorService` assembles a 4-section ranked report (deductions / taxes / filings / 401k-retirement) from existing OptimizationFinding + TaxRulesEngineService outputs. Generated by a queued job (`GenerateOptimizationReport`), stored in an `OptimizationReport` model (additive migration), marked stale on: new document extraction, bank sync, interview answer, profile change. Claude writes narrative prose ONLY — every number pre-computed; payloads exclude dollar figures the same way NarrationService does (3rd and FINAL permitted Claude call site of the milestone).

### D2 — Disclaimers (RPT-03)
Persistent, non-globally-dismissable educational disclaimers on every report section AND every optimization surface. "May/could/consider" framing. Include the year-end awareness section (RPT-08) as educational surfacing (no deadline pressure tactics; Dec-31 items framed as "commonly reviewed before year end").

### D3 — Export (RPT-04)
PDF via the existing dompdf pipeline (mirror TaxExportService patterns). Include the RIA-reframed educational glossary lines approved under default ruling R1 [owner review pending] in the report glossary where relevant.

### D4 — Document intake (DOC-01/02/03/05/06/07)
New `TaxDocumentCategory` enum cases for the six new doc types, reusing the v2.0 two-pass classify→extract pipeline. Screenshots/images via the existing Claude vision pattern (base64, no new library). Extraction results feed IncomeOptimizerDataAssemblerService and mark the report stale. DOC-05: the P11 interview's docs_missing affordance now wires to actual vault upload. DOC-07 (BINDING owner Decision 4): extracted facts enter as PROPOSALS with per-field confidence → USER CONFIRMS in UI before any write; user-entered values never silently overwritten; provenance recorded (STORE-03).

### D5 — Feature surface (UI-01/02/03)
- UI-01: "Optimize My Income" nav item in AuthenticatedLayout with badge (pending red-flag questions count) — ADDITIVE nav entry, nothing existing renamed/moved.
- UI-02: dedicated page: findings list → guided interview (P11 components: InterviewCard/SuggestedConfirmCard) → report view. The 12-surface "Tax Savings Control Center" concept is the FRAMING north star (organize by surfaces the user can act on) — not a literal 12-module build.
- UI-03: educational framing + inline disclaimer on every surface.
- **User/Family Profile (owner Decision 5, default ruling: option (a))**: new nav item/page hosting financial + enhanced-tax + family/spouse/dependents profile INCLUDING the AI-onboarding upload flow ("fastest path to a complete profile is uploading a paystub") and the LearnedTaxFactsSection (built in P11). Settings KEEPS account/security. Display labels additive only — no route/file renames.

### D6 — Frontend implementation (owner Decisions 6 + 7, BINDING)
Every frontend task: consult ui-ux-pro-max (python3 .claude/skills/ui-ux-pro-max/scripts/search.py) + apply /frontend-design:frontend-design principles + soft-skill (high-end-visual-design) + taste-skill; ELEVATE DON'T REPLACE (sw-* tokens are the baseline to polish — no palette swaps/restyles of existing pages); taste-skill v2 BLOCKING AUDITS per task in writing: em-dash, Pre-Flight §14, Preservation audit (empty except plan-granted additions: the two new nav items), Brand fidelity.
