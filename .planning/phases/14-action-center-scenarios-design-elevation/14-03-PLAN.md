<objective>
Build the read-side fact resolution substrate for scenarios (SCN-02): `ScenarioFactResolverService` and the citable `ScenarioFactSet` model + migration. The resolver walks each fact's config-declared source-priority chain (with alias fallback and deterministic derivations), classifies every resolution as `known` vs `confirmed` (§A.7 two-tier), and can freeze the current resolution into a versioned, HMAC-hashed, encrypted fact set that scenarios and checklist steps cite (D9.2 fact-gating, D10.6 grounded-in-confirmed-facts). It never mutates the snapshot, never writes facts, and never calls Claude.

Purpose: A single provenance-consistent read side so readiness (14-05), the solver baseline (14-06), and checklist gating (14-08) all resolve the same values the same way (M15).
Output: The resolver service, the ScenarioFactSet model + additive migration, and their tests (§T.1–2, §T.7).
</objective>
